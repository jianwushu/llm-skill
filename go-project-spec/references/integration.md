# 北向集成

全部是可选集成：需求里没有的依赖不建文件、不加依赖、不加配置节。

## 位置与注入

1. **收口之后只在 `internal/client` 构造**：service / engine / handler 通过构造函数注入**最小接口**（1–3 个方法）。禁止在业务代码里 `http.Get`、`redis.NewClient`、`mqtt.NewClient`。
2. **尚未收口时例外**：只有 1–2 处固定上游，允许在 service 里直接用 `http.Client`（必须带 Timeout）；出现第 2 处再收口。
3. **一个依赖一个文件**：`httpclient.go` / `mqtt.go` / `mq.go` / `redis.go`。同类多实例（多个上游）由构造函数接收配置，不从全局取。
4. **装配期创建 + 登记关闭**：进 `closers`，退出逆序关闭。
5. **配置化**：地址、超时、重试、池大小、并发数全部来自 YAML；密钥只写被 gitignore 的配置文件，不进日志。
6. **可选依赖允许降级**：不可用时返回 `nil` + `Warn`，上层返回明确错误而非 panic。
7. **可观测**：每次调用记录依赖名、耗时、结果；失败计数用于判断熔断/降级。

## HTTP：先判断要不要建客户端

出站调用先按最小需求做。默认直接用 `http.Client{Timeout: 10s}` + `http.NewRequestWithContext`，不建包。收口之后，下面几件事**各自独立判定**，只做命中的那些——它们没有先后等级，也不成套：

| 能力 | 触发条件 | 漏了会怎样 |
|---|---|---|
| 收口成客户端 | 调用点 ≥2，或要统一观测/测试替身 | 每处各写一套超时与错误处理 |
| 三段超时 | 收口之后（最小实现只有 `Client.Timeout` + ctx） | 某个环节永远等 |
| 重试 + 退避 | 方法是幂等的，且上游确有瞬时失败 | 偶发失败直接抛给用户 |
| 目标校验 | 地址有一段由调用方决定 | 用户能拿它探内网、读云元数据 |
| 响应体限流 | 上游响应体大小不可预期 | 一个大响应打爆内存 |

小工具只调一个固定内网接口：收口都不用做，`http.Client{Timeout: 10s}` 加 ctx 就是完整正确的实现。

项目侧收口后做三件事：配置节（`http_timeout_s`，要重试才加 `http_retries`，地址可控才加 `ssrf_policy` / `ssrf_allow_hosts`）、装配注入 + `CloseIdleConnections` 登记为 closer、错误映射（目标被拦 → 400；上游 4xx → 502/400 按语义；超时 → 504；其余 → 500；不把上游错误原文返回前端）。

### 超时与错误分类

- **三段超时**：连接（`Dialer.Timeout`）、整体（`Client.Timeout`）、**调用方 ctx 截止时间**。缺一个就有环节永远等。最小实现至少满足后两个。
- **错误分类只在要做重试时才有意义**：网络错误 / 5xx / 429 可重试；4xx 不重试（调用方错误）；解析失败不重试但日志带原始片段；`context.Canceled`、`DeadlineExceeded` **不重试**。不重试时只需分清"4xx 是调用方的错、5xx 是上游的错"。

### 重试

```go
attempts := 1
if isIdempotent(method) {        // GET/HEAD/PUT/DELETE/OPTIONS
    attempts = c.retries + 1
}
// 退避：wait = base << (attempt-1) + rand(wait/2)，且 select 监听 ctx.Done()
```

POST/PATCH 默认不重试。要重试必须同时具备：上游支持幂等键、键随请求发送、上游对同键返回同一结果。缺一个，重试就是重复写入。

### 目标校验：按地址可控性选策略

**先确认是否适用**：目标地址全部写在配置文件里、没有外部输入能影响它 → 跳过本节，不是缺陷。

「拒绝回环/私网」对面向用户输入 URL 的工具必要，但工业内网、私有云、边缘网关里 `10.x`、`192.168.x`、`127.0.0.1` 往往正是**合法上游**。一刀切会让功能不可用，然后被"临时注释掉校验"绕过，等于没有防护。

| 场景 | 策略 | 行为 |
|---|---|---|
| URL 来自前端/请求参数/用户配置 | `deny_private`（默认） | 拒绝回环、私网、链路本地、未指定地址 |
| 上游写在配置文件里的可信内网 | `allow_private` | 允许私网与回环，仍拒绝链路本地与云元数据 |
| 半动态上游（域名/网段清单） | `allow_hosts` | 只允许白名单内主机名、`*.后缀`、IP 前缀、CIDR |

**任何策略下都必须拒绝云元数据地址**（可达即可窃取实例凭证）：`169.254.169.254`、`169.254.170.2`、`100.100.100.200`、`fd00:ec2::254`、`metadata.google.internal`。

三层缺一不可：

1. **入口校验**：协议只允许 http/https，主机名/IP 按策略判定。
2. **拨号期 IP 校验**（`Dialer.Control`）：拿到**已解析**的 IP 再判定。只有这层能防 DNS Rebinding（校验时解析到公网，拨号时解析到内网）。
3. **重定向逐跳校验**（`CheckRedirect`）：每跳重新走入口校验，并限制跳数（10）。只校验 URL 字符串的，一次 302 就绕过全部检查。

启动时把生效策略打进日志，运维才知道当前是哪个档。

## 收发方向归位不同

连接类集成天然有两个方向，**不要用同一个构造函数把两边绑在一起**：

| 方向 | 形态 | 归位 |
|---|---|---|
| **接收**（订阅/监听/消费） | 长驻：连接常开，消息随时到达，处理时机不由调用方决定 | 客户端维护订阅表，业务侧**注册 handler**，不新增层 |
| **发送**（发布/推送） | 请求-响应：调一次等一个结果 | 客户端暴露**一个方法**，按最小接口注入给需要它的功能 |

### 接收侧：注册 handler，不新建层

1. **订阅关系登记在客户端已有的订阅表上**：`Subscribe(topic, handler)`，handler 就是业务侧的函数或方法。不要因为"常驻"新建 `internal/daemon/<x>.go`，也不要造"消息服务层"。
2. **不套五态状态机**。`daemon` 面向"任务有生命周期、从 DB/队列捞、要抢占/重试/断点续跑"；订阅是消息到达即处理，落在轻量档：注册表 + 固定 worker 就够（判定见 `tasks.md`）。只有出现"多实例竞争同一份待办"或"需要断点续跑"时才升级。
3. **回调只投递，不跑业务**：回调里解析 + 投递到带缓冲队列，由固定 worker 消费。回调跑耗时逻辑会拖住收包循环。
4. **关闭顺序**：退订 → 停止投递 → 排空在途（带超时上限）→ 断连。

### 发送侧：一个方法，注入给用的人

客户端只暴露 `Publish(ctx, topic, payload) error` 一类方法，业务侧拿到的是最小接口而非具体类型。不需要发送的功能不注入。发布是"一个动作"，不是"一层业务"，不要为它建 `MessageService`。

### 装配顺序

```go
mq := client.NewMQTT(opts)              // 客户端只负责连接与投递
cmdSvc := service.NewCommandService(mq) // 注入发布接口
err := mq.Subscribe("app/data/+", cmdSvc.Handle)  // 业务 handler 后注册
closers = append(closers, func() { _ = mq.Close() })
```

顺序天然线性：客户端不认识 service，service 只认识接口。

**反例**：把 handler 塞进客户端构造函数（`NewMQTT(opts, handler)`）会造出「客户端要 handler、service 要客户端」的循环，只能靠闭包占位或两阶段装配硬绕。这不是"双向通信的固有复杂度"，是接口方向选错了。

## MQTT 连接细节（paho.mqtt.golang）

- **QoS**：状态类 0/1；关键指令 1 + 业务幂等；QoS 2 成本高，小工具不用。
- **`ClientID` 必须唯一**：多实例加主机名/序号。
- **断线重连后必须重订阅**：订阅表在 `OnConnectHandler` 里恢复，首次连接与重连走同一路径。漏了这条不会报错，只是静默不再收消息。
- **退出**：`Unsubscribe` + `Disconnect(250)`；用遗嘱消息标记离线。
- **队列满**：QoS 0 丢弃并计数即可；**QoS 1 不能静默丢弃**（等于降级成 QoS 0），要么加大队列，要么落盘/落库重试。
- **断线期间 Publish**：明确选"快速失败"还是"排队等重连"，不要让它阻塞到 ctx 超时才报错；选排队的必须给队列上限。

## Redis（go-redis v9）

- **key 统一前缀** `app:<domain>:<id>`，前缀集中定义常量，避免多应用共用实例冲突。
- **写缓存必须带 TTL**（除非永久映射），否则内存无上限增长。
- 读失败按「未命中」降级：记日志 + 继续查 DB，不让缓存故障拖垮主流程。
- 分布式锁 `SET key owner NX PX 3000` 获取，释放用 Lua 校验 owner 后删除；锁必须有过期时间。
- 防穿透空结果也缓存短 TTL；热点 key 过期加随机抖动防雪崩。
- 禁止 `KEYS *`、`FLUSHALL`；批量用 `MGET` / `Pipeline`。

## 消息队列（RabbitMQ / Kafka / RocketMQ）

- **生产者**：开确认（RabbitMQ `Confirm`、Kafka `acks=all`）；失败要有落库重试或死信，不能只打日志。
- **消费者**：手动 ack，处理成功后才 ack；失败按次数进重试队列/死信，禁止无限重试。
- **幂等**：至少一次投递，消费端必须幂等（唯一键去重表 / 状态机判断）。
- **背压**：消费并发固定（worker 池），不要"收到就起 goroutine"；耗时任务设 `prefetch`。
- **关闭**：停止拉取 → 等在途处理完 → 关连接。

## 反模式

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| `&http.Client{}` 零值 | 请求永久挂起 | 显式 Timeout |
| 多处散落的第三方调用 | 无法限流/重试/观测 | 出现第 2 处就收口 |
| 不判断幂等就重试 POST | 重复下单/扣款 | 幂等键或只重试幂等方法 |
| 一律禁止私网 | 内网功能不可用 → 校验被注释掉 | 按可控性分三档 |
| 只校验 URL 字符串 | 302 / DNS Rebinding 绕过 | 入口 + 拨号 + 重定向三层 |
| MQTT 回调里同步做重活 | 丢消息、心跳超时 | 投递到 worker 队列 |
| 把 handler 塞进客户端构造函数 | 循环依赖，被迫两阶段装配 | 先建客户端，后 `Subscribe` |
| 给订阅套五态状态机 | 复杂度翻倍、收益为零 | 注册表 + worker |
| Redis 无 TTL、`KEYS *` | 内存暴涨、阻塞实例 | 必设 TTL，用 SCAN |
| 消费端自动 ack | 处理失败即丢消息 | 手动 ack + 死信 |
| 把上游错误原文返回前端 | 泄漏内部信息 | 统一映射 + 日志留详情 |

## 新增依赖检查清单

1. `config` 加配置节（地址/超时/重试/池大小/策略），补默认值与校验——默认值必须写进生成的文件。
2. `internal/client/<dep>.go` 实现客户端：方法接收 ctx、设置超时、分类错误。
3. 定义最小接口注入 service/engine；**若还要接收，先建客户端，再 `Subscribe(topic, handler)`**。
4. 装配处创建并登记 `closers`（接收方向的顺序：退订 → 排空 → 断连）。
5. 启动连通性检查：Ping/Connect 失败按 fail fast 或降级 + `Warn` 明确选一种。
6. 埋点（依赖名、耗时、结果）与 README 配置说明。
