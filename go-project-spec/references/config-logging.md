# 配置与日志

两者耦合：日志的目录、级别、保留天数全部来自配置，且日志必须在配置校验通过之后才能初始化。

## 配置

1. **单一来源**：结构定义、加载、默认值、校验全在 `internal/config` 一个包。其他包只拿结构体，禁止自己读文件。
2. **只读 YAML，不读环境变量**。需要区分环境就准备多份配置文件，由启动参数或部署目录切换。混入环境变量后"这个值到底从哪来"无法回答。
3. **加载顺序固定**：默认值 → 配置文件 → 校验 → 回填默认值。顺序写死在代码里，不靠调用方自觉。
4. **fail fast**：必需项缺失、取值非法、结构损坏，一律启动失败并打印**具体字段名与可取值**。
5. **配置即文档**：首启生成的默认文件要含全部可配项与注释，用户改这一个文件就够。
6. **敏感项**：DSN、口令写本地配置文件并加入 `.gitignore`；回显配置时打码，不进日志。

### 首启找不到配置文件

| 方式 | 行为 | 适用 |
|---|---|---|
| **生成并退出**（默认） | 生成含全部默认项的文件，打印路径与提示，**exit 0** | 首次部署需人工确认端口、数据库地址 |
| 内置默认值继续启动 | 用默认值启动并打印明显告警 | 容器化、一次性工具，要求零配置也能跑 |

默认值不安全时（默认端口会撞、默认库会连错）必须选第一种。生成后退出**不是错误**：用可辨识的哨兵错误（如 `ErrConfigFileCreated`）区分，退出码保持 0，否则部署脚本和守护进程会判定崩溃并反复重启。

### 结构校验

反序列化成功不代表结构正确。典型坏情况是缩进错误让某节变成标量，解析不报错，整节被静默丢弃、回落到默认值：

```yaml
log: ⟶  level: info     # 反序列化不报错，log 节被丢弃
```

所以要显式检查「顶层是映射，每个节也是映射」，否则报错并提示检查缩进：

```go
if doc.Kind != yaml.MappingNode { return errors.New("top level must be a mapping") }
for i := 0; i+1 < len(doc.Content); i += 2 {
    if doc.Content[i+1].Kind != yaml.MappingNode {
        return fmt.Errorf("section %q must be a mapping (check indentation)", doc.Content[i].Value)
    }
}
```

静默回退比报错危险：用户以为改了配置，实际跑的是默认值。

### 默认值填充

- 集中在一个函数（`defaults()` / `fillDefaults()`），不散落到使用处。
- **零值不一定是未配置**：`0` 对"不重试"这类字段是合法值，判定用 `< 0` 或 `*int`，不要一律 `== 0` 就覆盖。
- 默认值必须写进生成出来的配置文件，让用户看得到。只在 `enabled=true` 时才填默认值，会让生成的文件里全是 `0` 和空串。

## 日志

### 何时需要文件日志

| 场景 | 文件日志 |
|---|---|
| 交互式 CLI，用户看得到 stdout | 不需要 |
| 常驻服务、守护进程、定时任务 | **需要**，否则排障只能靠复现 |
| 单次运行的工具（转换、批处理） | 需要「结果文件 + 失败原因」，日志可选 |

不要为了统一给一次性脚本加按天滚动和清理任务，那只是多出一堆没人看的文件。

### 条款

1. **唯一初始化点**：全项目一处 `slog.SetDefault`，位于配置校验之后、其他组件之前。其他包只用 `slog.Info/Error`，不各自构造 handler。
2. **级别来自配置**，取值 `debug|info|warn|error`，非法值**启动即失败**。静默降级到 info 会让"打错字却看起来正常"成为最难发现的配置错误。
3. **输出**：控制台 + 文件，文件按天滚动，命名 `app-YYYY-MM-DD.log`。
4. **初始化参数用组件自己的 `Options`**（目录、级别、滚动、保留天数、清理间隔），装配处从项目配置映射过来。组件一旦 import 项目的 `config` 就不能跨项目复用。
5. **关闭函数随初始化返回**，由装配处登记并**最后关闭**。提前关日志会丢掉"关闭过程中"的错误日志，恰好是排障最需要的那几条。
6. **滚动与清理是两件事**：滚动负责换文件，清理负责删老文件，分开才能各配频率。

### 两个容易写错的地方

- **写入时检测跨天，不用定时器**。定时在 0 点切换，进程那一刻可能没日志、也可能被挂起，结果跨天第一条日志写进昨天的文件。检测到日期变化时再懒创建新文件——`level: error` 且当天无错误时不该凭空多一个空文件。
- **清理只删自己认识的文件**：只匹配 `app-YYYY-MM-DD.log` 且日期早于保留天数。同目录可能被用户放了别的日志或备份，`*.log` 全删是事故。清理失败（目录不存在、文件被占用）只 `Warn`，不能让服务起不来。频率默认 24 小时一次、启动时先扫一次即可。

### 字段

- 结构化键值，不拼字符串：`slog.Info("user created", "id", id)`。
- 固定键名便于检索：`module`、`request_id`、`elapsed_ms`、`retries`、`err`。`err` 统一用这个键，不混 `error`/`e`/`cause`。
- 请求日志（方法、路径、状态码、耗时）放中间件，业务关键节点在 service 打点，不在业务层重复记录请求信息。
- 口令、token、完整 DSN 不入日志，必要时脱敏为 `***`。

## 反模式

| 反模式 | 后果 | 正确做法 |
|---|---|---|
| 各处 `os.Getenv` / 各处读配置文件 | 无法回答值从哪来 | 单一加载点 |
| 反序列化成功就认为配置正确 | 缩进错误静默用默认值 | 显式结构校验 |
| 配置错误用默认值兜底继续跑 | 生产连错库、开错端口 | fail fast 并打印字段名 |
| 生成配置后返回非 0 退出码 | 部署脚本判定崩溃反复重启 | 哨兵错误 + exit 0 |
| 默认值散落在使用处 | 改默认值要翻十个文件 | 集中 `fillDefaults` |
| 每个包各自 `slog.New` | 一半日志不落盘 | 唯一初始化点 |
| 定时器切文件 | 跨天首条日志进昨天文件 | 写入时检测日期 |
| 清理 `*.log` 全删 | 误删同目录用户文件 | 只匹配自己的命名 |
| 关日志排在前面 | 关闭过程的错误日志丢失 | 逆序关闭，日志最后 |

## 校验

```bash
# 删掉配置文件启动：生成默认配置并 exit 0
# 写入 level: verbose：拒绝启动并指出字段
# 写入坏缩进：报 section "log" must be a mapping
go test ./internal/logger -run 'TestCleanExpired|TestDailyWriter' -v
# 手工：打一条日志，确认 logs/app-YYYY-MM-DD.log 出现且与 stdout 一致
```
